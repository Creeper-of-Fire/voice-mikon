# voice-mikon-next 验证壳

这个仓库**不是** voice-mikon 的新版本，而是一个**验证壳**：用来证明
"C# + Avalonia + NativeAOT 能同时做到 透明 / 不抢焦点 / 点击穿透 / 拖拽 / 右键菜单 / 动画"。

验证通过后，`src/VmNext.Shell/` 里的窗口层代码会直接成为正式重构的骨架。

- 自动化验证报告：[`docs/feasibility.md`](docs/feasibility.md)
- 实际技术栈：Avalonia **11.3.23**（csproj 写的是 `11.*` 浮动版本）/ .NET **10**（net10.0）/ NativeAOT
- 实测内存：JIT 工作集约 **120MB**、AOT 约 **85MB** —— 窗口层结论成立，但**离 20–50MB 的常驻目标还差不少**，
  差距来自 Avalonia 的 Skia 渲染后端（详见报告结论）。
- 窗口层骨架：`src/VmNext.Shell/`
  - `NativeMethods.cs` —— 全部 Win32 P/Invoke（集中一处，带中文 XML 注释）
  - `OverlayWindow.cs` —— 透明 / 不激活 / 置顶 / 点击穿透 / 拖拽 的窗口子类
  - `Theme.cs` —— 颜色令牌 + 运行时主题切换（类名是 `OverlayTheme`，原因见报告）
  - `HotKeyWindow.cs` —— 全局热键（窗口不抢焦点 ⇒ 收不到键盘事件，热键是必需品）
  - `OverlayProbe.cs` —— A1–A6 的自动化自检

## 怎么跑

```
demo A:  dotnet run --project src/demos/Demo.A.Static
demo B:  dotnet run --project src/demos/Demo.B.Morph
demo C:  dotnet run --project src/demos/Demo.C.Interactive
自动化:  dotnet run --project tests/VmNext.AutoCheck
```

- 三个 demo 启动时会在控制台打印一行引导（验什么、怎么看、怎么退）。
- 按 **Q** 退出（会占用全局 Q 键；因为窗口不抢焦点，收不到普通按键，只能用全局热键）。
- 自动化程序跑完 A1–A13，会把结果写进 `docs/feasibility.md`（大约 3–5 分钟，其中大半花在 NativeAOT 发布上）。
- 自动化期间窗口只会在**屏幕右下角**短暂出现，不会乱动你的鼠标键盘（全程只用 `PostMessage` + 查询类 API）。

## Demo A — 透明 / 不激活 / 穿透 / 菜单

跑起来后按顺序看：

- [ ] 球下面透出的是桌面，不是灰底/白底/黑底
      ✗ 失败现象：球周围一圈方形色块
- [ ] 先点一下你正在用的别的窗口，再点球、再右键球：那个窗口的标题栏一直是激活态
      ✗ 失败现象：点球瞬间编辑器光标消失/标题栏变灰
- [ ] 右键菜单能弹出、能点菜单项、点完焦点还在原来的窗口
      ✗ 失败现象：右键球没有任何反应，或菜单弹不出来
- [ ] 点球四角（透明处）：点击穿到下层窗口（比如点到桌面图标会选中它）
      ✗ 失败现象：四角点击没反应

> 补充：球在屏幕右下角、贴边 48px。如果你屏幕右边是别的显示器，把球拖过去也能看。

## Demo B — 动画

- [ ] 点球（或按空格）：球在约 0.8 秒内长成胶囊，过渡连续
      ✗ 失败现象：跳变/闪烁/有残影
- [ ] 形变期间透明区域没有灰带、没有半透明控件浮在红底上
      ✗ 失败现象：胶囊周围出现一圈灰色方块或半透明色块
- [ ] 波形条从右往左滚，左边 10px 渐隐，没有条纹闪烁
      ✗ 失败现象：波形条一格一格跳、或者整条波形突然消失/整块出现
- [ ] loader 在转，麦克风图标在呼吸（约 3 秒一个周期）
      ✗ 失败现象：loader 不转，或麦克风没有呼吸效果（整体静止）
- [ ] 按 T 切主题：颜色平滑过渡，深浅两套下文字都看得清
      ✗ 失败现象：颜色瞬间跳变（闪一下），或者浅色主题下文字看不清/看不见
- [ ] 整体看 10 秒，有没有掉帧感
      ✗ 失败现象：明显卡顿、波形一顿一顿、loader 转起来像慢动作

## Demo C — 拖拽 / 多屏 / 文字选择

- [ ] 按住球拖 100px 再松手：跟手、松手不跳
      ✗ 失败现象：球跟不上鼠标、松手后位置突然跳一下
- [ ] （有多屏的话）拖到另一块屏：球大小随缩放变，位置对
      ✗ 失败现象：球没变大/变小，或者球和鼠标错位、跑到屏幕外面
- [ ] 胶囊里的文字能选中，Ctrl+C 后到别处能粘贴出来
      ⚠ 这条是已知边界点，不工作就记现象，不算整体失败
      ✗ 失败现象：鼠标拖不选文字（选不中），或者选中了但 Ctrl+C 没反应、粘贴出来是空的

> Demo C 的窗口**允许激活**（不加 `WS_EX_NOACTIVATE`），否则拿不到键盘焦点、Ctrl+C 一定不工作。
> 这是覆盖层设计必须先做的取舍，详见 `docs/feasibility.md` 的结论部分。
